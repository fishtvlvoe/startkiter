## Purpose

目前 `CourseInstructor` 只是一張沒人用的資料表：沒有管理畫面、沒有權限檢查。補上完整的多講師指派與權限隔離，讓一堂課能由多位講師共同管理，且講師只能看到自己被授權的範圍。

## ADDED Requirements

### Requirement: 用戶管理頁角色分頁

用戶管理頁依角色分頁顯示（全部/學員/講師/管理員），並提供角色指派 UI。

#### Scenario: 總管理員將使用者指派為講師

- **GIVEN** 總管理員在用戶管理頁「學員」分頁看到某使用者
- **WHEN** 總管理員選擇將該使用者角色改為「講師」並二次確認
- **THEN** 該使用者出現在「講師」分頁，且該操作只有總管理員角色能執行，講師角色無法修改他人角色

### Requirement: 課程講師授權範圍

課程資訊頁可指定哪些講師能管理該課程；未指定時預設所有講師都可管理。

#### Scenario: 課程未指定講師時的預設權限

- **GIVEN** 某課程尚未指定任何 `CourseInstructor` 記錄
- **WHEN** 任一講師角色使用者查看課程管理列表
- **THEN** 該課程出現在其可管理列表中（預設全講師可管）

#### Scenario: 課程指定特定講師後的權限收斂

- **GIVEN** 某課程已指定講師 A、B 為 `CourseInstructor`
- **WHEN** 講師 C（未被指定）查看課程管理列表
- **THEN** 該課程不出現在講師 C 的可管理列表中；講師 A、B 可正常存取

### Requirement: 後端權限檢查（非僅前端隱藏）

所有課程管理相關 API 都必須用共用權限 helper（`requireCourseManageAccess`/`manageableCourseWhereForUser`）驗證，不能只靠前端選單隱藏。

#### Scenario: 講師嘗試直接呼叫未授權課程的管理 API

- **GIVEN** 講師 C 沒有被指定管理課程 X
- **WHEN** 講師 C 直接呼叫課程 X 的管理 API（略過前端選單）
- **THEN** API 回傳權限拒絕（403），不回傳課程 X 的任何管理資料

### Requirement: 講師後台選單可見性限制

#### Scenario: 講師登入後台看不到總管理員專屬選單

- **WHEN** 講師角色登入後台
- **THEN** 選單不顯示銷售分析、系統設定、隱私權、服務條款、組合包等 5 項總管理員專屬功能

### Requirement: 優惠券權限隔離

#### Scenario: 講師只能看到自己課程的優惠券

- **WHEN** 講師角色進入優惠券管理頁
- **THEN** 只能看到與操作自己有管理權限課程相關的優惠券，看不到其他講師課程的優惠券設定
