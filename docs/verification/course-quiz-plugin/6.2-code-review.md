## 第一輪發現與修正

1. High — 作答時間可由客戶端偽造：原本 submit 接受 client-controlled `startedAt`，可藉由偽造目前時間繞過限時。修正為 `packages/course-quiz/quiz-session.ts` 使用 `BETTER_AUTH_SECRET` 的 HMAC-SHA256 啟動 token，token 綁定 `userId`、`pluginContentId` 與伺服器產生的 `startedAt`；API submit 只接受並驗證 token，並由伺服器計算 elapsed time。
2. Medium — 後台設定不足：原本 time limit、shuffle、答案顯示、題目內容與題型為硬編碼。`quiz-admin-form.tsx` 已補上時間限制、題目／選項洗牌、答案策略、四種題型、選項／正解編輯、新增／刪除題目與配分。
3. Medium — 多選題測試缺少不完整選項案例。已補上缺少一個正解時必須判錯的測試，並補上填空答案的 trim／大小寫不敏感測試。

## Correctness

- 四種題型（單選、多選、是非、填空）皆有測試；多選題驗證順序不同與不完整答案。
- `showAnswers=NEVER` 由 `toLearnerQuiz` 丟棄 `correctAnswer`／`explanation`，submit response 也只回傳 score／passed。
- `QuizAttempt` 獨立記錄 score、passed、server-calculated elapsed time；`hasPassedQuiz` 只查詢本人通過紀錄，不改課程解鎖邏輯。
- `MOUNT_POINTS` 使用 auto route `/quiz` 與 operator route `/quiz-admin`，未改動既有課程 block 架構。

## Security

- 啟動 token 使用 HMAC-SHA256 與 `timingSafeEqual`，竄改 token 與錯誤 secret 會拒絕；缺少 `BETTER_AUTH_SECRET` 時 fail closed。
- submit 驗證 token 的 user 與 quiz 綁定，跨 quiz 重用合法 token 實測回傳 400。
- 未登入頁面實測 307 導向登入，quiz start API 實測 401。
- operator 建立測驗受 `quizOperatorProcedure` 與 server-side redirect 保護。
- 學員 quiz get 受 lesson published／free preview／課程權限檢查；未發現可讀取他人 `QuizAttempt` 的路徑。
- `showAnswers=NEVER` 實測 API 原始 response 只有 `{score, passed}`，沒有 `correctQuestionIds` 或 `correctAnswers`。

## Performance

- `/quiz/[pluginContentId]` 以一次 `getAccessibleQuiz` 查詢取得課程、單元與 PluginContent，未發現逐題或逐選項 N+1 查詢。
- `hasPassedQuiz` 是單一 `findFirst`，沒有載入不必要的作答明細。
- 啟動 token 是無狀態 HMAC，不新增 session／token 資料表或額外持久化查詢。
