StartKiter · Creator platform blueprint · 2026-10-12

一套創作者平台，兩條不同產品生命線

StartKiter 管理創作者的內容、名單、銷售與課程權限；買家拿到 CodePackage 後，建立自己的 SaaS，並管理自己的客戶與訂閱。即時直播與預錄 Webinar 也分開設計，讓未來加功能時不會串錯權限。

01 · 一張圖看懂

共用一個創作者平台，資料與權限分清楚

創作者工作台串起 CRM、內容、漏斗、自動化、銷售與 Webinar；AI 只拿到被允許的資料，買家程式包則成為買家自己的 SaaS。

5 個責任區
實線表示資料／流程交接；外部影音服務只提供播放與錄影。 5 個區塊；課程、買家 SaaS、直播權限互不混用。

03 · 直播與 Webinar

Systeme.io Webinar 不是即時直播

REA 看到的免費控制台沒有 Webinar 選單；官方說明列出 Webinar／Unlimited 方案可建立 Evergreen Webinar，但原生不提供即時直播。StartKiter 必須把兩種播放方式分開。

技術來源：官方文件＋REA
Evergreen · 預錄常青內容

錄影自己按時段播放

報名頁 → 感謝頁 → Webinar／conference 頁；依立即觀看、指定時段或 just-in-time 規則播放預錄內容。

  • 提醒信可由註冊或開播事件觸發。
  • 錄影內可安排 Offer CTA、replay 與後續自動化。
  • 是預錄內容，不代表主持人正在即時直播。
Live · 真正即時活動

主持人與觀眾同時在線

StartKiter 管報名、名單、提醒、Offer 與出席紀錄；外部影音 provider 負責視訊、音訊、聊天室與錄影。

  • 先選 provider adapter；供應商尚未拍板。
  • 結束後出席、no-show、錄影 ready 成為可追蹤事件。
  • Provider 無法使用時，不發錯誤或失效的加入連結。

04 · AI 怎麼協作

AI 可以幫忙做草稿；平台仍掌握權限與最後確認

AI 依使用者原有權限，讀取允許的名單、活動與營運資料，產生摘要、草稿與建議。它不會悄悄寄出訊息、改價、退款或改會員資格。

選定工作區先確認 actor、workspace 與可讀模組

有權限的人核准寄送、發布、收款或授權前先預覽

05 · 買家怎麼建 SaaS

買家拿到的是程式包，不是整站所有課程權限

買家可以用程式包打造自己的 SaaS、會員網站或付費頁面。買家的終端客戶、登入、組織、訂閱與資料庫，都在買家部署的產品裡各自管理。

下游資料由買家擁有
購買 CodePackage單獨販售，或由課程／Bundle Offer 一起交付
取得私人 repo依 license 取得更新、商用與支援規則
用 Code 模式開發Codex CLI、Codex Desktop 或 Claude Desktop Code mode
部署自己的 SaaS自有 Auth、資料、付款與客戶權限

技術證據的邊界

WebinarKit 前端頁載入 jQuery 3.7.1、vendor.bundle.js、theme.bundle.js、Feather／FontAwesome、Google Tag 與外部聊天 widget。REA 頁面觀察只能證明瀏覽器載入的資源與可見請求，不等於伺服器框架、資料庫、影音 CDN 或完整即時影音技術架構。

Systeme.io 控制台的資源觀察受第三方來源授權範圍限制；本次不能確認其前端框架或後端實作。官方文件已足以確認 Webinar 的產品邊界：自動化播放，不提供原生即時直播。
